# Боевой движок «Битой масти»

`src/core/battle-engine.js` — независимое от интерфейса ядро дуэли. Оно не читает DOM, не обращается к `localStorage` и не принимает решений за бота. Благодаря этому один и тот же движок можно использовать в браузере, тестах, на будущем сервере мультиплеера и при воспроизведении матча.

## Главные свойства

- детерминированный генератор случайности с `seed`;
- отдельное состояние игрока и дилера;
- у обеих сторон есть колода, рука, сброс и изгнание;
- здоровье, щит, энергия, статусы и раунды;
- кража, блокировка, поломка и сжигание карт;
- команды не изменяют входное состояние, а возвращают новое;
- каждое действие создаёт события и записывается в журнал;
- состояние проверяется после каждой команды;
- сохранения имеют версию и точку миграции;
- матч можно повторить по исходной конфигурации, `seed` и журналу команд.

## Публичный API

```js
const state = BitayaMastBattle.createBattle(config);
const result = BitayaMastBattle.executeCommand(state, {
  type: "playCard",
  actorId: "player",
  cardInstanceId: "c12",
  targetId: "dealer"
});
```

Поддерживаемые команды первого этапа:

- `playCard`
- `endTurn`
- `discardCard`
- `chooseTarget`

Основные события:

- `BATTLE_STARTED`
- `TURN_STARTED`
- `CARD_DRAWN`
- `CARD_PLAYED`
- `DAMAGE_DEALT`
- `SHIELD_GAINED`
- `HEALED`
- `STATUS_APPLIED`
- `CARD_STOLEN`
- `CARD_BROKEN`
- `CARD_BLOCKED`
- `CARD_BURNED`
- `TURN_ENDED`
- `BATTLE_FINISHED`

## Формат карты

```js
{
  id: "pickpocket",
  name: "Карманник",
  type: "skill",
  rarity: "rare",
  cost: 2,
  target: "opponent",
  effects: [
    { op: "steal", zones: ["hand"] }
  ]
}
```

Карты являются данными. Движок исполняет универсальные операции из `effects`, поэтому добавление новой карты не требует отдельного `if` в боевой логике.

## Повтор матча

Каждая команда получает `preHash` и `postHash`. Метод `replayBattle(initialConfig, commands)` повторно создаёт бой и проверяет, что результат каждой команды совпал с исходным матчем. Это основа для отладки, повторов и проверки действий на сервере.

## Граница этапа 1

На этом этапе ядро ещё не заменяет старую боевую сцену. Подключение нового интерфейса, анимаций и первого полноценного дилера выполняется на этапе 2. Старый прототип продолжает работать во время разработки.
